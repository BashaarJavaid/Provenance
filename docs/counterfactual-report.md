# Memory made incident #2 cost 34% more wall-clock and changed nothing it concluded

**What this is:** ROADMAP item 32 — the measurement [`ADR-023`](./adr/ADR-023-the-bounded-retry.md), [`ADR-025`](./adr/ADR-025-class-beliefs-and-the-advisory-cap.md) and [`ADR-026`](./adr/ADR-026-incident-three-and-the-cold-entity.md) each deferred a causation claim to, and which items 18 and 24 both declined to make without it. §8.2 asks for it as the sixth UI surface: *"the measured A/B (memory on vs `--memory-disabled`): wall-clock, tool calls, tokens, hypotheses evaluated before the correct one."*

**The number does not support the claim those items declined to make.** On this incident, recall cost time and tokens and bought nothing that any of the four metrics can see. Item 18's note predicted exactly this and said why; this report leads with it rather than finding a metric that flatters the design. The decisions behind the measurement are in [`ADR-034`](./adr/ADR-034-the-counterfactual-ab.md).

**Baseline.** Six live incidents measured, from twelve run against real Firestore and real Gemini on `provenance-hackathon` on 2026-08-26. Every number below comes from the six artifacts in [`counterfactual/`](./counterfactual/) and nothing else.

## What the numbers say

**Recall costs about 13 seconds and about 150 tokens, and the arms do not overlap.** Wall-clock ran 49.7 / 52.3 / 55.7 with memory and 38.7 / 39.0 / 41.8 without: two separated ranges, not two samples of one. The slowdown is real and it is a **34%** increase on the median. It is also unsurprising — recall is a Firestore read plus an embedding call plus a longer domain prompt, all of it on the critical path before the graph is built.

**Nothing downstream moved at all.** Every one of the six runs made 4 model calls, considered 2 hypotheses, selected `config_regression`, executed `v42 → v41`, verified `CONFIRMED`, and committed `belief-inventory-api` v2 at 0.60. The two arms are identical in every respect except what they spent.

**So on this fixture memory is a pure cost.** That is the honest headline, and it is worth more to the project than a favourable one, because the design never claimed otherwise: the claim in §6 is that memory makes belief *governed and inspectable*, not that it makes one incident faster. Item 32 was scoped to check the speed claim nobody had made, and it turns out not to hold.

## Why it could not have gone the other way, and why the fixture stays

**`sre_infra.py` already contains the answer.** Its prompt has carried a config-regression hint since item 9:

> "If the deployed config version is ahead of the last known-good one and the deviation began after it, a configuration regression is the leading candidate."

On this fixture that precondition is true, so the domain agent reaches `config_regression` with or without a recalled belief. There is nothing left for recall to contribute to the diagnosis, and a metric measuring the diagnosis therefore has no room to move. **This is a ceiling effect, not a finding about memory.**

Item 18's note recorded the same thing before this measurement existed — *"the claim is unfalsifiable as the line words it"* — and rejected removing the hint to make it falsifiable, because incident #1 is a cold case that would lose its only hint, putting the verified 10/10 at risk and contaminating items 19, 20 and 32. That trade still holds after seeing the number: an A/B with more headroom would have cost three earlier items their evidence.

**What this measurement does not license.** It does not show memory is worthless, and it does not show memory helps. It shows that on an incident whose agent already knows the answer, recall is overhead — which is the narrowest true reading, and the only one these six runs support.

## The two metrics the item asked for that do not exist

§8.2 names four metrics. Two of them are not properties of this system, and saying so is part of the result rather than a caveat on it.

**"Tool calls" — there are none.** No agent in this fleet is constructed with `tools=`; all six are output-schema-constrained `LlmAgent`s, and `provenance/tools.py` is a declarative action-class table ([`ADR-011`](./adr/ADR-011-tool-registry-and-action-validation.md)) rather than an ADK tool registry. The count would be zero in both arms and would measure nothing. What the table reports instead is **model calls** — requests to Gemini, added in item 32 as `provenance.reasoning.model_calls` and counted in `_reasoning.py`'s `after_model_callback` *before* the `usage_metadata` check, so a response that reports no tokens still counts as the request it was.

**"Hypotheses evaluated before the correct one" — no ordering is stored.** Nothing in the fleet records which hypotheses were considered or in what sequence. What exists is `hypotheses_considered`, an integer the agent asserts about its own reasoning, which has been telemetry-only since item 9 for precisely this reason. It is reported, labelled **model-asserted**, in the table and on the panel. §1.1 property 3 is untouched — it forbids a model-asserted number being an input to a *deterministic decision*, and nothing deterministic reads this one — but a reader is owed the distinction between a number a system observed and a number a model claimed.

## Method

1. **One variable.** The arms differ only in `run_incident(memory=...)`, which skips `recall.recall()` and changes nothing else. The belief is present in the store for both arms and §2.2's commit runs for both — **both arms end at belief v2**, asserted per arm in `tests/test_counterfactual.py`. Disabling the commit as well would have been a second variable and the delta would have been unattributable.
2. **A trial is a pair of incidents.** Incident #2's premise is a belief already in memory, so each measured run is preceded by a cold incident #1 that writes v1, then `restore_service()` to re-inject the same deviation with memory left standing. Only the second incident is measured. Twelve incidents produced six measurements.
3. **The arms are interleaved** on/off/on/off/on/off rather than run in blocks, so drift in Vertex latency across the session lands on both arms.
4. **Median, not mean,** over three runs. A single 429-and-retry moves a mean of three and does not move a median of three.
5. **Wall-clock is measured locally**, with `time.monotonic()` around the `run_incident()` call, and deliberately not taken from the span timestamps: a Cloud Trace read-back lags the run by up to two minutes, and the number that matters is the one a person waited through — recall included, since recall is the thing under test.
6. **The other three metrics come off Cloud Trace**, summed over the incident's `provenance.reasoning.chain` spans. Tokens and model calls are summed over *every* step, because what an arm costs is what the whole loop spent. The hypothesis count is read from the `diagnosis` step alone — summing it across the Orchestrator's classification and the verifier's read-back would produce a number about nothing.
7. **A trace cannot name its own arm.** With recall skipped, the spans carry an empty `provenance.recall.belief_ids`, which is exactly what a cold incident #1 produces — so "memory disabled" and "memory found nothing" are indistinguishable on the trace. The run artifact records the arm; nothing else does, deliberately ([`ADR-034`](./adr/ADR-034-the-counterfactual-ab.md) reason 8).

## Reproducing it

The offline half needs no credentials, no network and no cloud project:

```
.venv/bin/python scripts/verify_counterfactual.py
```

It re-derives the table from `docs/counterfactual/run-*.json`, and exits non-zero unless the JSON served at `GET /counterfactual` **and** the markdown block above are both exactly what those artifacts derive. `tests/test_counterfactual.py` runs it, so CI catches a report edited away from its own evidence.

The live half is twelve real incidents against the real fixture, and writes and restores live state per trial:

```
GOOGLE_CLOUD_PROJECT=provenance-hackathon GOOGLE_GENAI_USE_VERTEXAI=1 \
GOOGLE_CLOUD_LOCATION=global PROVENANCE_PLANNER_KEY="$(cat ~/planner.pem)" \
.venv/bin/python scripts/verify_counterfactual.py --record --runs 3
```

`docs/counterfactual/session.log` is the unedited console output of the run these numbers come from — literally unedited, which means roughly two thirds of it is gRPC and google-auth chatter on stderr. Python block-buffers stdout through a pipe while that chatter is unbuffered, so the two streams are not chronologically interleaved in the file; the script's own lines are in order relative to each other.
