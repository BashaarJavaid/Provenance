# ADR-024 — The second domain: the graph holds every domain, and each domain holds its own facts

**Status:** Accepted (ROADMAP item 21). Answers the `half_life_domain` revisit clauses in [`ADR-017`](./ADR-017-novelty-and-the-accumulated-evidence-set.md) and [`ADR-018`](./ADR-018-the-conflict-rule-and-the-standing-counter.md), and the one-domain-node shape [`ADR-013`](./ADR-013-trigger-stream-and-incident-graph.md) built; implements `ARCHITECTURE.md` §5.4's generality claim, which item 22 then measures.

**Decision:** `provenance/agents/supply_chain.py` is the second domain and is the whole of it. `incident.DOMAINS` becomes a typed `Domain` entry carrying `agent_id`, `scope`, `target_kind`, `build` and `seed`, and **the graph's nodes, the Orchestrator's vocabulary, the routing edge map and the session state are all comprehended out of that one dict** — so a third domain adds one file and one entry and nothing else. `route` gains a fail-closed check that the classified domain's `target_kind` matches the target's actual kind. The Planner gains one `{planner_context}` slot filled by the routed domain in place of the service facts it used to name directly. `policy.HALF_LIFE_DAYS` becomes a per-domain lookup, with both published values at 30 days. A supply-chain incident ends `HELD` at score **11**, and that is the item's shape rather than a shortfall.

**Reasoning, in order of weight:**

1. **The graph is built before classification runs, so it must hold every domain (primary reason).** `build_graph()` built one `sre_infra` node and routed `{"ROUTED": domain_agent, ...}`; a second domain cannot be selected after the fact because there is no "after the fact" — `run_incident()` constructs the whole workflow and then runs it. So `route` sets `ctx.route` to the **domain name** and the edge map is `{**domain_agents, "UNROUTABLE": halt}`, comprehended out of `DOMAINS`. Every agent is built and at most one runs, which costs one `LlmAgent` construction per domain per incident and buys the property §5.4 actually claims: the line count in `build_graph()` does not move when a domain is added. The two alternatives both cost more than they save. Classifying **outside** the graph — as a plain awaited step, the way recall already is — would let the single routed agent be chosen before the workflow exists, but it moves a reasoning agent out of the Graph Runtime that ADR-007 and ADR-013 chose deliberately, and the trace stops showing where the incident went. A single **dispatcher** node that internally picks an agent keeps the edge list at one entry, but routing stops being an edge, which is the precedent §7.1's "the re-plan is a real edge" set and the reason an `UNROUTABLE` incident is visible in the span tree at all.
2. **State is seeded before classification too, and that is what forced the seeder to be a merge rather than a lookup.** `_seed_state()` read `company.service(trigger.target)` unconditionally and seeded nine service-shaped keys; a supplier target raised `KeyError` before any agent ran. The fix cannot be "pick the domain's seeder", because the domain is not known yet — recall and state seeding both happen before the Orchestrator has said anything. So every domain's `seed_state()` runs on every incident and returns its own keys either way, with `"n/a"` for a target that is not its kind. ADK resolves an instruction's `{key}` out of session state at interpolation time, so a key an instruction names and nothing seeded is a crash rather than a blank; the merge is what guarantees there is no classification the Orchestrator can return that produces one. The alternative — resolve the entity's kind first and run only that kind's seeder — is tidier by a dozen dead keys and strictly worse: a supplier misclassified as `infrastructure` would then die at interpolation, which is an exception where §7.3 wants a visible outcome.
3. **Seeders own disjoint keys, except `planner_context`, which exactly one of them fills.** Dict merge order decides collisions, so two seeders returning the same key would make `DOMAINS` insertion order load-bearing — a bug that appears the day someone reorders a dict literal. Every private key is prefixed by its domain's vocabulary and a test asserts the sets do not intersect. `planner_context` is the deliberate exception because it is the one thing both domains *must* be able to produce, and each returns it only for a target of its own kind, so exactly one fills it per incident and the shared block in `_seed_state()` supplies the empty default. Without that rule, whichever domain came last in `DOMAINS` would blank the routed one's Planner context, and the failure would be a subtly worse prompt rather than an error.
4. **The kind check is §7.3's posture, not a second judgment, and it is what makes reason 2 safe.** `route`'s docstring says "registry lookup, not judgement", and a mismatch check reads like judgment creeping in. It is not: it compares two facts, the classified domain's declared `target_kind` and the entity model's answer for this target, neither of which a model produced. What it prevents is concrete — a supplier handed to the SRE agent can only diagnose the `"n/a"` placeholders reason 2 requires the seeder to return, and a diagnosis built on placeholders is worse than no diagnosis because it looks like one. Leaving it out was the alternative and it makes the merged seeding safe only as long as the Orchestrator behaves, which is exactly the kind of guarantee §1.1 exists to replace with a mechanism.
5. **A supply-chain incident ends `HELD` at 11, and forcing it further would have cost three control-plane files.** The only supplier-scoped tool is `DISABLE_COMPLIANCE_CHECKS`, which §4.2 scores `4 + 2 + 2 + 3` against a tier-1 supplier. Item 21's verify line is "routes, diagnoses, and **proposes**", and a hold satisfies it exactly: the proposal is typed, validated, scored and signed by the same code path incident #1 uses, and §2.1 stage 7 parks it on a human. Adding a third, benign supplier tool to reach execution would have meant an entry in `tools.TOOLS`, an entry in `risk.BASE`, a branch in `executor.execute()` and new fields on the frozen `Supplier` — three of the five files §5.4 promises stay at zero — to demonstrate an execute/verify/learn path items 9 through 20 have already proven four ways. The consequence is that the incident writes **no belief**, which is §7.2 with no branch needed: nothing executed, so nothing was verified, so there is nothing to learn. This is also §4.2's second worked example reached by a fleet rather than asserted by a table-driven test, for the first time in the repo.
6. **The Planner stopped naming service facts, because it plans for every domain.** Its instruction interpolated `{current_config_version}`, `{known_good_version}` and `{nominal_error_rate}` and its `success_predicate` rule was written entirely around error-rate thresholds. On a supplier incident those slots would read `"n/a"` beside a rule that does not apply — inert, since a held incident verifies nothing, but visibly wrong on half the fleet's incidents and a trap the moment a second domain ever executes. One `{planner_context}` slot, filled by the routed domain, is what the file needed. **Item 11.5's predicate floor and item 20's literal-values clause moved into `agents/sre_infra.py` unchanged in wording**: both were found live, both are facts about infrastructure rather than about planning, and the live regression is what says the move cost them nothing. Branching the instruction on target kind was the alternative and puts domain knowledge back in the shared file the split exists to empty.
7. **`half_life_domain` is a real per-domain lookup whose two values are equal, and that is the honest state.** ADR-017 reason 7 declined to build the table at item 13 because "a dict keyed by one key varies by nothing", and named item 21 as when it earns its existence. It does: a second domain has beliefs of its own, `commit()` already carries `domain`, and the number is now looked up per domain everywhere it is used — in `contributions()`, in the stored `half_life_days` and in `expires_at`. What did **not** happen is inventing a difference. A longer supply-chain half-life is arguable, since a contractual record ages more slowly than a live service observation, but nothing here has measured it and ADR-002's defence of these numbers is that they are inspectable and fixed rather than tuned. It would also not be free: `SUP-042`'s chain is committed and append-only, `scripts/seed_belief.py` has no `--reset` on purpose, and changing the clock moves the inspector's live recomputed confidence and the `expires_at` on a belief items 27 and 28 attack and whose survival is the demo's closing shot. A future value is one line in one dict; a future value chosen today would be a number with no provenance in a project whose entire claim is that numbers have provenance.
8. **The lookup raises rather than defaulting, and something checks the keys are all there.** `HALF_LIFE_DAYS[domain]` is a `KeyError` for an unpublished domain — the posture `risk.BASE` and `tools.tool_for()` already take, and the alternative (default to 30.0) would let a belief silently borrow another domain's decay clock, which is precisely the kind of unpublished number ADR-002 forbids. A fail-closed raise is only fail-closed if it cannot fire in practice, so `tests/test_policy.py` asserts that every domain any registry record may write beliefs in has a published half-life — the same guard `tests/test_risk.py` puts on `risk.BASE` against `tools.TOOLS`. And because both values are 30 today, nothing observable would distinguish a real lookup from the old constant, so a test patches one entry and asserts only that domain's rows decay differently.
9. **`Diagnosis` moved to `_reasoning.py` because it is a contract, not a domain fact.** `incident.hand_off` reads its five fields by name for whichever agent ran, which makes it the interface between the domain layer and the Planner. Leaving it in `sre_infra.py` gave the second domain two bad options: copy it verbatim — two schemas one node reads identically, which is two schemas that drift — or import it, which makes the domain files a dependency chain rather than the peers §5.4's claim is about.
10. **`company.described()` is the one polymorphic entity read, and it is scoped to the callers that genuinely cannot know the kind.** ADR-009 kept the collections typed precisely so a caller always knows which it holds, and item 6's tool schema names that kind. Two callers predate any of that within an incident: the recall query and the routing kind check both run before a tool has been resolved. `described()` serves exactly those, returns kind/tier/description, and raises on an unknown id like its two typed siblings. Every authorization path still goes through `service()` / `supplier()`, so the rule ADR-009 stated is narrowed by two named callers rather than abandoned. `recall.query_text()`'s literal word `"service"` was the other half of the same defect — a supplier incident would have queried the index with a sentence calling its supplier a service — and the substitution keeps the query shape item 16 measured `SIMILARITY_FLOOR` against byte-identical for the infrastructure case.
11. **`trigger_signal` gained one value under item 2's condition.** `compliance_lapse`, with the module, `ARCHITECTURE.md` §8.1 and `tests/test_telemetry_schema.py` in one commit. A lapsed supplier certification reported as an `error_rate` would be an untrue fact on the incident span, which is the one thing §8.1's vocabulary exists to prevent. Widening the Literal to a plain `str` was the alternative and removes the out-of-vocabulary check that makes it a contract rather than a comment. **No sixth span shape and no new attribute key** — the streak since item 16 holds.
12. **The verify script mutates nothing, the first since item 8 with no teardown, and it guards the opposite.** There is no fault to inject (the trigger carries the deviation) and no execution to undo, so `refuse_if_dirty()` and a `try/finally` restore would have nothing to act on. What it does instead is read `SUP-042`'s belief chain before and after and assert it byte-identical: this is the one script that runs an incident against the entity items 27 and 28 attack, so "it left memory alone" is the guarantee worth checking. It also asserts recall handed the agent the AT_RISK belief **before** waking the fleet, so the premise of "diagnoses against prior belief" is a fact rather than an assumption whose failure would surface four minutes later from the trace as the wrong finding.

**What this deliberately does not do.** It does not touch `gateway.py`, `risk.py`, `action.py`, `tools.py`, `executor.py`, `beliefs.py`, `audit.py`, `registry.py` or `credentials.py`. It adds **no registry record**: `supply-chain-agent` has existed since item 5 with `memory_domains=("supply-chain",)` and `tool_scope=()`, and needs no tool scope because §2.1 has the Planner emit the Action. It adds **no fault switch**, since nothing executes. And it does not give the second domain a `_LEARNS_FROM` entry or a negative status — ADR-022's revisit clause expected item 21 to need one, and the honest answer is that a domain whose only action is held learns nothing, so the constant stays infrastructure-only until a supply-chain incident can execute.

**A spelling tension, stated rather than corrected.** §3.2's figure writes the domain `supply_chain`; the live value is `supply-chain`, which is what `registry.AGENTS` seeds as this agent's `memory_domains` and what `SUP-042`'s committed chain carries. An append-only belief store is not a place to correct a spelling, and `policy._decide()` refuses `DOMAIN_NOT_HELD` on any mismatch, so the hyphen is what the code uses everywhere. §3.2's figure is left as written, like its unreachable confidence numbers (ADR-021), with the as-built note carrying the real value.

**What this costs:** one new agent file, one new verify script, a typed `Domain` entry, and the changed lines in `incident.py`, `policy.py`, `planner.py`, `sre_infra.py`, `company.py`, `recall.py`, `telemetry.py`, `app.py` and `_reasoning.py` (which this list omitted) — counted, itemized and reported rather than hidden in [`docs/generality-report.md`](../generality-report.md), which is item 22. The estimate this paragraph carried before that count was *roughly forty*, and the measured behavioural figure is **207**. No new dependency, no new GCP resource, nothing that bills while idle. One `verify_supply_chain.py` run is three `gemini-2.5-pro` calls and no Flash call, about 45 seconds.

**Revisit when:** a third domain arrives, which is the real test of whether reasons 1–3 delivered what they claim — the prediction is one agent file and one `DOMAINS` entry, and a diff larger than that falsifies this ADR rather than merely inconveniencing it; a supply-chain incident can execute something, at which point `_LEARNS_FROM` needs a second domain's status and ADR-022's revisit clause reopens; a domain needs two half-lives or the flip threshold wants to be per-domain too (ADR-018's clause, and it should not be, unless a document says so); item 23's class beliefs need `nominate()` to filter by domain, which it deliberately does not today; or item 30's approval queue gives the `HELD` supply-chain incident somewhere to actually land, which is the first thing that makes reason 5's stopping point visible to a user rather than only to a test.

**Alternatives considered:** a third, benign supplier tool so the incident executes (reason 5); classifying outside the graph, and a single dispatcher node (reason 1); picking the seeder by entity kind, and seeding after classification (reason 2); letting seeders collide and fixing `DOMAINS` order (reason 3); no kind check (reason 4); leaving `planner.py` untouched and living with `"n/a"` slots, and branching its instruction on kind (reason 6); a genuinely different supply-chain half-life (reason 7); defaulting an unpublished domain to 30 days (reason 8); copying `Diagnosis` into the new file, or importing it from `sre_infra` (reason 9); a `try`/`except` over `company.service()` in `incident.py` instead of `described()`, and dropping the entity facts from the recall query altogether (reason 10 — the second re-opens item 16's floor measurement); reusing `error_rate` as the supplier signal (reason 11); and extending `scripts/verify_incident_one.py` with a `--supply-chain` flag (its whole structure is dirty-check plus inject plus restore, none of which this arc has, so it would inherit teardown for state it never touches).
