# ADR-020 — Recall as built: query-time embeddings, and a statement on the root document

**Status:** Accepted (ROADMAP item 16). Implements [`ADR-005`](./ADR-005-recall-index-nominates-store-decides.md), which decided the division of labour and is not revisited here.

**Decision:** `provenance/recall.py` implements §6.6 as two independent reads. Entity beliefs come back by exact key through `beliefs.belief_id_for()` and `beliefs.current()`, with no model involved at all. Class beliefs are nominated by embedding their statements and the incident's typed facts with Vertex AI `text-embedding-005` **at query time**, ranking by cosine in Python, and taking the top `NOMINATE_K = 3` above `SIMILARITY_FLOOR = 0.55`. The index reads **root documents only**; the store resolves the ids it returns and drops `RETRACTED` and `UNKNOWN`. `Recalled` keeps the nomination list beside the survivors, and the authorization ledger cites **entity ids only**.

**Reasoning, in order of weight:**

1. **No Vector Search index endpoint, because of the cost ceiling (primary reason).** A deployed Vertex AI Vector Search index bills per node-hour whether or not it serves a query — the same trap `CLAUDE.md` flags for the Gemma sanitizer, and enough to consume the $300 credit while nobody is watching. Against a corpus that will be in the single digits until well past this hackathon, it would buy latency nobody is short of. Embedding at query time costs a fraction of a cent per incident and bills nothing at rest. This is a ceiling, not a preference: the upgrade path is Vector Search and `nominate()`'s signature does not change when it is taken.
2. **Nothing stores a vector, which removes a whole failure mode.** A stored embedding is a second artefact that can disagree with the statement it came from — after a re-embedding with a different model, or a write that lands without its vector. Recomputing per query means the index is never stale by construction. The cost is one batched call per incident, and `nominate()` returns before making it when no class belief exists, which is why incident #1 spends nothing on this.
3. **`statement` is copied onto the belief root document, so ADR-005's separation is structural.** ADR-005 says the index "never sees confidence, status, or currency". The statement lives on the version, so an index reading `current()` would be touching exactly the object it is not allowed to consult, and the separation would survive only as a convention a reviewer has to re-verify. A root document carries `belief_id`, `entity`, `domain`, `scope`, `statement` and `created_at` — no status and no confidence — so `beliefs.class_statements()` structurally cannot see currency. `append()` writes the root create-if-absent, so the statement is written once at v1 and never rewritten, which is also correct: a class belief's statement is what identifies it.
4. **The nomination list is kept and put on the span.** §6.6's guarantee is that a retracted belief can be the closest match and still reach nobody. A span carrying only the survivors cannot distinguish that from an index that nominated nothing, so `provenance.recall.nominated_ids` joins `recall.belief_ids` — the first new attribute key since item 2 defined the vocabulary, taken with §8.1 and `tests/test_telemetry_schema.py` in the same commit. It earns the exception the way `evidence.ids` beside `novel_count` does: the gap between the two *is* the audit trail.
5. **The ledger cites entity ids only.** §6.2 caps a class belief as ADVISORY ONLY — it may reorder what a domain agent investigates and may never be the evidence that authorizes an action. `authorizations/{id}.belief_ids` is the record of what an action rested on, so citing a class belief there would make §6.4's retraction flag actions on grounds §6.2 says they could not have had. `Recalled` therefore keeps the two sets apart and exposes `entity_ids` separately, which makes the cap a property of the type rather than a rule `incident.py` has to remember.
6. **The two reads fail independently.** An unreachable embedding API yields *no* class nominations rather than all of them, and the exact-key read proceeds regardless (§7.3). §6.1 promises a mechanical read; making it depend on a model being up would be strictly weaker than the guarantee it replaces. An unreadable *store*, by contrast, propagates — "the store was unreadable" and "the organization believes nothing" must not look alike. A nominated id the store cannot produce is dropped rather than raised: that is a stale nomination, not a corrupt belief.

**What the floor is, and what it is not — measured, not assumed.** `SIMILARITY_FLOOR` was chosen against real vectors, and the measurement is the part worth keeping. Against an `error_rate_spike on inventory-api` query, `text-embedding-005` scored three infrastructure statements at 0.628–0.731 and an unrelated supply-chain statement at 0.523 — a real separation, and what the floor rests on. But the *same* statements scored 0.696 against a deliberately absurd query about a cafeteria menu. So the number discriminates between statements for one query, which is what nomination is, and emphatically **not** between a sensible query and a nonsense one. An earlier draft of `scripts/verify_recall.py` tried to prove the floor with an unrelated query and would have enshrined the opposite conclusion. No score is read as a confidence anywhere downstream, because the index proposes and the store decides — which is the one property that makes a weak instrument safe to use here.

**Revisit when:** class-belief volume makes brute-force ranking or nomination quality a measured bottleneck — at which point ADR-005's revisit clause applies and Vector Search is the named upgrade. The division of labour is not up for revision either way.

**Alternatives considered:** a deployed Vertex AI Vector Search index (rejected on the cost ceiling above — the whole credit in a few weeks of being left up); storing the vector on the belief document at commit time (rejected: puts a model call inside §2.2's deterministic write path and adds an artefact that can disagree with its statement); reading the statement off `current()` rather than the root (rejected: makes the index's blindness a promise instead of a fact); synthesising a statement for entity beliefs so the index has something to work on before item 23 (rejected: §3.2 makes `statement` CLASS-only and §6.1 is exact-key by design — an entity belief in the index is the RAG-shaped mistake ADR-005 exists to refuse); deferring the index entirely to item 23 (rejected: the item's verify line is a §10 row, and hand-seeded fixtures prove a mechanism ahead of its producer exactly as items 8, 14 and 15 did).
