# ADR-015 — The trace UI reads the stream in process, polls, and stays a static file

**Status:** Accepted

**Decision:** The two §8.2 surfaces item 11 fills — the live fleet view and the gateway ledger — read a **bounded in-process buffer of live span objects**, fed by a second `SpanProcessor` on the same `TracerProvider` that exports to Cloud Trace, served unauthenticated at `GET /trace` and **polled once a second** by the same hand-written JavaScript in the same single static file item 3 shipped. Not a Cloud Trace read-back, not Server-Sent Events, not a framework. `scripts/deploy.sh` drops to `--max-instances=1` as a direct consequence.

**Reasoning, in order of weight:**

1. **Cloud Trace cannot render an incident as it runs (primary reason).** Item 11's verify line is "a cold browser session can watch incident #1 end to end," and item 2 measured Cloud Trace indexing lag at ~15s typical and ~2 minutes worst — on top of `BatchSpanProcessor`'s own batching, which by design does not flush per span. A panel fed from the v1 read-back API would be a replay of an incident that finished a minute ago, which is not what "renders the incident as it runs" says. The in-process buffer holds **the same span objects** `BatchSpanProcessor` exports, not a copy of them, so §8's "the UI reads that same stream" stays literally true while Cloud Trace remains the durable record.
2. **Capture is at span *start*, because "current state" is the surface's whole job.** §8.2 defines the fleet view as "agents, **current state**, which belief each is reading." A `provenance.reasoning.chain` span stays open for the entire model call — measured at ~20s per Pro call in item 9 — so an `on_end`-only processor leaves the panel blank for the first twenty seconds of a filmed take and then paints a finished row. `SpanProcessor.on_start` hands over the live `Span`, whose attributes are readable while it is still recording and whose `end_time` is `None` until it closes, so one deque entry serves both states and `snapshot()` reads current state at poll time. This also made the endpoint *simpler*: one record shape rather than a start record and an end record to reconcile.
3. **Polling beats SSE at this size.** The gain is under one second of latency. The cost is an async generator, keep-alive pings, `EventSource` reconnect handling, and a long-held connection against Cloud Run's request timeout. The shell already polls `/health` on an interval; the trace poller copies that shape, and because a span mutates after it is first served (running → done), the endpoint serves the **whole buffer** each poll and the client repaints keyed by `span_id`. A cursor would have needed all of the snapshot's de-duplication logic *plus* a sequence counter.
4. **`GET /trace` is unauthenticated, and that is the point.** `POST /trigger` is guarded because a trigger spends model tokens against a fixed credit; a read spends nothing. The cold judge of item 11's verify line and of item 36 has no token, so guarding the read would make the item's own criterion unreachable. What bounds the exposure is §8.1's redaction rule — identifiers, hashes, enums and numbers, never content — which `tests/test_telemetry_schema.py` enforces at emit and `tests/test_app.py` now re-checks on the bytes the endpoint actually serves. `THREAT_MODEL.md` records that agent ids, standings, risk arithmetic and decision signatures are therefore public.
5. **ADR-008's revisit clause, answered: still no framework.** That ADR deferred the question to "item 11, when the live fleet view and ledger exist and their update pattern is known." It is now known, and it is fetch-JSON-and-repaint over five span shapes — no client-side state beyond a form's four fields, no routing, no optimistic updates. A build stage, a lockfile and a second toolchain in CI still buy nothing. **Answered at item 31, and the answer is still no** ([`ADR-033`](./ADR-033-the-approval-card.md) reason 6): the approval card writes, awaits, and renders what came back, so the honest test this reason was waiting for produced no client-side write state to manage.

**Consequence — `configure_tracing()` is no longer a no-op without a project.** It now always builds the `TracerProvider` and attaches the buffer; only the Cloud Trace exporter is conditional, and the return value narrows to mean exactly "Cloud Trace export is wired" (which is what `/health`'s `tracing` field always reported). Without this the UI would be blank locally and in CI, and the offline half of this item could not exist. `tests/conftest.py` attaches the same buffer to the one global provider for the same reason that file exists at all.

**Consequence — the buffer filters by span name.** The processor sits on the provider ADK also auto-instruments, so it saw roughly twenty ADK spans per incident (`agent …`, `call_llm …`, one per graph node) beside our five shapes. Those belong in Cloud Trace and still reach it through the other processor, but in the UI buffer they quadrupled the polled payload and cut its history to a quarter. `on_start` therefore keeps only names carrying the `provenance.` prefix — which §8.1 introduced for precisely this discrimination. The UI already filtered them out by name; this makes `BUFFER_SIZE` mean what it claims.

**Consequence — `--max-instances=1`.** The buffer is per process, so a `POST /trigger` that blocks for ~60s and the 1/s `GET /trace` polls beside it have to reach the same instance. At this volume Cloud Run would almost certainly keep them together; "almost certainly" is not a property to discover during a filmed take. `--min-instances=0` is unchanged, so this lowers the cost ceiling rather than raising it.

**What this deliberately does not do:** fill the other four surfaces (belief inspector item 17, registry panel item 28, approval card item 31, counterfactual panel item 32 — their placeholders are untouched); persist the buffer across a container restart; render more than the newest trace; give the Executor a row, because it emits no span by design (ADR-014) and inferring one would have the UI assert state the trace cannot prove; or expose any write path to the fault-injection switch, which stays in `scripts/inject_fault.py` where its `try/finally` restore covers it.

**Amended at item 17 — the one stream is still one stream, and it is no longer the only source.** This ADR's framing was that the UI reads the span stream and nothing else. Item 17's belief inspector reads `GET /belief/{entity}` instead, and had to: §8.2 asks that surface for evidence, arithmetic, a chain and a decay clock, all of which are *content*, and §8.1 keeps content off spans on purpose — enforced, not merely intended, by `tests/test_telemetry_schema.py`. So this is not a gap a sixth span shape could close; admitting content to spans would trade the property that makes `/trace` safe to publish for one panel. The fleet view and the ledger are unchanged and still read the buffer. Reasoning in [`ADR-021`](./ADR-021-the-belief-inspector.md), which also records why the new route is a live Firestore read rather than a snapshot: items 28 and 29 both write to the belief it renders.

**Revisit when:** a second incident can run concurrently (the UI already groups by `trace_id`, but it renders only the newest); or a surface needs history across a restart, at which point Cloud Trace read-back is the upgrade path at the lag reason 1 rejected it for; or a surface acquires client-side write state that has to be reconciled against the server — item 31's approval card was the expected candidate and did not, so the next one is genuinely unknown.

**Alternatives considered:** Cloud Trace v1 read-back (reason 1); a Firestore span-mirror collection (durable and cross-instance, at the cost of a second write path for the audit stream and a Firestore write per span — and it solves a problem `--max-instances=1` solves for free); Server-Sent Events (reason 3); an `?after=<seq>` delta cursor (reason 3); `on_end`-only capture (reason 2); guarding the read with the trigger token (reason 4); React + Vite (reason 5, and ADR-008 reason 3); backgrounding `POST /trigger` so it returns an incident id immediately (changes item 9's documented response shape and breaks `scripts/verify_incident_one.py`'s assertions on its body, and an unawaited task on a scale-to-zero instance can be killed mid-incident — the UI simply does not await the fetch instead).
